# W3D — 三维点云基础设施语义分割（KPConv + DALES）

> 本文档定义 W3D 项目的算法设计、模型选型、训练 pipeline 与部署方案。
> 对应代码仓库：https://github.com/Willis90/W3D

## 1. 项目目标

**愿景**：从机载激光雷达（LiDAR）点云中自动分割出**地面、植被、建筑、电力线、车辆、卡车、围栏、桥梁**八类基础设施要素，为电力巡检、城市建模、智慧城市等下游应用提供像素级（点级）精度的语义标注。

**核心问题**：

- 输入：无序、不均匀、千万量级的三维点云（每点含 xyz + 强度）
- 输出：与点等长的类别标签（8 类，0–7）
- 难点：电力线/围栏细长且点数稀少；建筑/植被局部几何差异大；点云稀疏且分布不均

**评测目标**：测试集上 mIoU ≥ 0.65（业内 DALES 公开报告 KPConv/RandLA-Net 大致 0.65–0.75 区间）。

## 2. 数据集：DALES

DALES（Dense Airborne LiDAR for Endangered Species / 大规模机载激光数据集）是最常用的机载 LiDAR 语义分割基准之一，包含 40 个场景、约 5 亿个点。

| 字段 | 说明 |
|---|---|
| 来源 | https://udayton.edu/engineering/research/centers/vision_lab/research_and_data/w3d_data.php （需注册） |
| 规模 | 40 scenes, ~5×10⁸ points |
| 平均点密度 | ~50 pts/m² |
| 坐标系 | UTM（米） |
| 类别数 | 8 类（含未标注 0） |
| 文件格式 | .ply（每点含 x/y/z/intensity/label） |

### 2.3 预处理

1. **坐标归一化**：每 scene 计算 xyz 的均值与标准差，按 (x-μ)/σ 归一化；推理时反归一化用于落盘
2. **强度归一化**：intensity / 255 → [0, 1]
3. **Tile 切分**：每原始 scene 用滑动窗口切成多个 4096 点的 tile，stride=2048（50% 重叠，推理时概率平均）
4. **KNN 预计算**：对每个 tile 预计算 k=16 邻居索引，缓存为 .npz

## 3. 算法：KPConv 轻量版

### 3.1 为什么选 KPConv

KPConv（Kernel Point Convolution，Thomas et al. ICCV 2019）的核心优势：

- **几何可解释性强**：核点位置固定在球面上，能捕捉电力线、围栏这种细长结构
- **不依赖体素化**：直接对无序点云操作，保留原始分辨率
- **核点学习**：每个卷积核学习 K 个核点位置 → 局部几何编码

相比替代方案：

- **PointNet++**：max-pool 损失几何信息，对细长结构不友好
- **RandLA-Net**：速度快但随机采样对稀疏类别不利
- **KPConv**：在电力线/围栏这类稀疏细长结构上表现最稳

### 3.2 核函数定义（Rigid Kernel）

rigid kernel 在**球面均匀采样 K=15 个固定核点**（不参与学习），位于半径 r 的球内：

```
kernel_points[K=15, 3] ← 预计算的固定位置（buffer）
对于每个 query 点 x：
    找 x 的 k=16 邻居 {x_i, f_i}
    对每个核点 kp_j：
        w_j = Σ_i (1/邻居数) * max(0, 1 - ||x - x_i - kp_j|| / σ) * MLP(...)
```

σ 是核点的影响半径，公式中 `max(0, 1 - d/σ)` 即**线性插值权重**，让距离核点越近的邻居贡献越大。

### 3.3 核心 Block

```python
class KPConvBlock(nn.Module):
    def __init__(self, in_feat, out_feat, K=15):
        self.kpconv = KPConvLayer(K, in_feat, out_feat)
        self.bn     = nn.BatchNorm1d(out_feat)
        self.act    = nn.LeakyReLU(0.1)
        self.shortcut = nn.Conv1d(in_feat, out_feat, 1) if in_feat != out_feat else nn.Identity()
    
    def forward(self, x, neighbors):
        # x: (N, in_feat), neighbors: (N, k)
        residual = self.shortcut(x)
        x = self.kpconv(x, neighbors)   # (N, out_feat)
        x = self.bn(x)
        x = self.act(x + residual)
        return x
```

### 3.4 U-Net 结构

| 层级 | 操作 | 特征维度 | 点数 | 备注 |
|------|------|---------|------|------|
| enc1 | KPConvBlock × 2 | 32 | N | 原始分辨率 |
| pool1 | 最远点采样 ×0.5 | 32 | N/2 | FPS |
| enc2 | KPConvBlock × 2 | 64 | N/2 | |
| pool2 | FPS ×0.5 | 64 | N/4 | |
| enc3 | KPConvBlock × 2 | 128 | N/4 | |
| pool3 | FPS ×0.5 | 128 | N/8 | |
| enc4 | KPConvBlock × 2 | 256 | N/8 | |
| pool4 | FPS ×0.5 | 256 | N/16 | |
| enc5 | KPConvBlock × 3 | 512 | N/16 | bottleneck |
| up4  | 插值 ×2 + skip | 256 | N/8 | nearest 插值 |
| dec4 | KPConvBlock × 2 | 256 | N/8 | |
| up3  | 插值 ×2 + skip | 128 | N/4 | |
| dec3 | KPConvBlock × 2 | 128 | N/4 | |
| up2  | 插值 ×2 + skip | 64  | N/2 | |
| dec2 | KPConvBlock × 2 | 64  | N/2 | |
| up1  | 插值 ×2 + skip | 32  | N   | |
| dec1 | KPConvBlock × 2 | 32  | N   | |
| head | 1×1 conv | num_classes | N | per-point logits |

### 3.5 输入特征

- xyz：3 维（已归一化）
- intensity：1 维（已归一化）
- 共 **in_features=4**

> 设计上预留了"类别 one-hot"扩展点（见 KPConv forward 的可选参数），但本次实现只使用 4 维特征，避免冷启动复杂度过高。

### 3.6 邻居查询：KNN (k=16)

- 训练时**在线 KNN**（每个 batch 重新算）
- 推理时**预计算 + 缓存**到 `data/dales/knn_cache/`，避免重复算

实现方式：手写 KNN（基于 PyTorch 向量化矩阵乘法 + topk），不依赖 torch_geometric，部署简单。

### 3.7 损失函数：加权交叉熵

```python
class_weights = 1 / log(1.02 + class_freq)   # 频次越低权重越高
loss = F.cross_entropy(logits, labels, weight=class_weights, ignore_index=-100)
```

- 自动从训练集统计类别频次
- 频次对数反比：电力线虽然只占 1%，但权重约 8x
- ignore_index=-100 处理 unknown 标签

### 3.8 评估指标

- **OA (Overall Accuracy)**：所有正确分类点 / 总点数
- **mIoU (mean Intersection over Union)**：8 类 IoU 的均值
- **per-class IoU**：8 类各自 IoU，打印表格
- **电力线 IoU 单独追踪**：业务最关心

## 4. 训练 Pipeline

### 4.1 优化器与学习率

- 优化器：**SGD**（momentum=0.9, weight_decay=1e-4）— KPConv 论文推荐
- 初始学习率：0.01
- 学习率调度：余弦退火（CosineAnnealingLR, T_max=epochs）
- Batch size：4（每个 tile 4096 点；12GB GPU 显存约 70–80% 利用率）
- Epochs：100

### 4.2 数据增强

| 增强 | 参数 | 作用 |
|------|------|------|
| random_rotation_z | [-π, π] | 绕 z 轴随机旋转 |
| random_scale | [0.9, 1.1] | 各向同性缩放 |
| random_jitter | σ=0.01, clip=0.05 | 高斯噪声 |
| random_dropout | max=0.2 | 随机丢掉最多 20% 点 |

### 4.3 验证与保存

- 每 epoch 训练结束 → 在 val set 评估 mIoU
- 保存 `checkpoints/best.pth`（mIoU 最高）
- 每 10 epoch 保存 `checkpoints/last.pth`
- TensorBoard 记录 loss / mIoU / per-class IoU

## 5. 推理与后处理

### 5.1 滑窗预测

- 原始 scene 切成 4096 点 tile，stride=2048（50% 重叠）
- 每个 tile 单独预测
- 重叠区域的预测概率**求平均**（probability average）
- 拼回完整点云，按 argmax 取最终标签

## 7. 部署

服务器环境：RTX 5070 (12GB VRAM), CUDA 12.8, Python 3.10, PyTorch 2.8, conda env `yolov8`。

```bash
# 1. 激活环境
conda activate yolov8

# 2. 拉代码
cd ~/projects && git clone https://github.com/Willis90/W3D.git
cd W3D

# 3. 数据准备（一次性）
bash scripts/download_dales.sh
python scripts/prepare_dales.py
python src/data/precompute_knn.py

# 4. 训练
python src/train.py --config configs/default.yaml

# 5. 评估
python src/eval.py --ckpt checkpoints/best.pth

# 6. 推理
python src/inference.py \
  --input /path/to/scene.ply \
  --output /path/to/pred.ply \
  --ckpt checkpoints/best.pth
```

## 8. 已知限制

| 限制 | 影响 | 缓解 |
|------|------|------|
| 电力线稀疏（~1%） | 加权 CE 仍可能漏检；mIoU 中此项 0.4 上下 | 后续可加 focal loss / 电力线专用 data augmentation |
| KPConv 无 deformable kernel | 对建筑屋顶等复杂形状拟合稍差 | 本期不实现，文档留接口 |
| 单卡 5070 12GB | batch=4 接近上限；tile 点数 4096 是上限 | 后续可换 A100 或缩 tile |
| 训练时长预估 | DALES 完整集 40 scene × 100 epoch × batch=4：约 **18–24 小时**（RTX 5070） | 后续可加 fp16 训练、缩短 epoch |
| 推理用 CPU 路径未优化 | 大量小 ply 推理时慢 | 后续可加 ONNX/TensorRT 导出 |
| 服务器 yolov8 env 共享 | 与 YOLO 项目共用 conda env，存在包冲突风险 | 建议长期拆出独立 `w3d` env |
